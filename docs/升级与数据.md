# 升级与数据处理

0.5.0-beta.5 WebUI 的升级、迁移和回退见[快速开始](zh-CN/quick-start.md#升级迁移与回退)。

## 旧版 Mac App

此说明随提示词结构更新准备，尚未代表对应版本已公开发布。不要把开发版安装包当作现有GitHub Release附件。

## 普通升级不会清空项目

1. 等生成任务结束，保存并退出工作台。
2. 备份整个数据目录，并保留旧App。macOS默认目录为用户主目录下的 Library/Application Support/AI Portrait Studio Standalone。完整备份应包含数据库、图片、任务记录及相关配置；授权文件属于私密数据，不发到GitHub、问题反馈或别人电脑。
3. 安装新版后先核对项目、图片和任务数量。旧项目保持原提示词，继续按旧的段落编辑方式工作；只有用户主动改变字段或引用才更新相应内容。
4. 新建项目使用新的拍摄要求结构：中性起点，整组风格可由镜头覆盖，姿态图片逐镜头保存；右侧补充与自写全文分开。
5. 想用新版重做旧项目，可先新建项目，通过“从其他项目复用”带入图片，再自行选择用于本次。旧词可粘贴到“自写全文”。现有“复制项目”会复制原格式，不会自动把旧稿转换成新结构。

新版不能恢复从未保存过的历史动作引用。旧项目若此前多个镜头共用同一动作图，需要逐镜头重新核对。

## 本地全新体验是明确选择的特殊构建

只有显式选择 fresh-profile 的本地构建，才使用独立目录：

~/Library/Application Support/AI Portrait Studio Standalone Prompt V2

这个选择不删除、不覆盖原目录。旧项目和照片保留在原目录及备份中，新目录没有原项目不表示原数据丢失。连接授权也不会自动迁移；如未连接，需要在新版里重新授权。

一般发行构建默认不带这个选择。维护者不得为了升级提示词而默认给所有用户换成空数据目录。

## 回退与数据恢复

- 保存、退出新版后，再使用保留的旧App及原数据目录。
- 不要用旧版写入包含新结构的数据目录。新版会识别更高的结构版本并限制编辑；旧版本不一定认识新格式。
- 如需回退新版期间产生的数据，先保留新版完整目录，另建副本进行恢复。不要用旧备份直接覆盖较新的照片或任务。
- 两个App不能同时操作同一个数据目录；不同测试/体验目录也不应自动互相合并。

## 反馈前核对

提供App版本、平台/模型名、操作步骤及必要截图即可。不要上传整个数据目录、授权文件、cookie或token。提示词和图片可能含私人创作内容，提交前自行决定哪些可公开。
